Project conventions are file-contract driven and intentionally simple. Reuse existing scripts and flows instead of creating parallel logic. User-specific customization belongs in `career-ops/config/profile.yml`, `career-ops/modes/_profile.md`, or `career-ops/article-digest.md`; do not put personalization in system-layer files like `modes/_shared.md`. Queue/tracker/report contracts matter: `pipeline.md` is the queue, tracker status canon comes from `career-ops/templates/states.yml`, tracker additions flow through merge scripts instead of direct new-row edits, and report numbering stays sequential. Code style is pragmatic: Node uses plain `.mjs` scripts, Go dashboard uses compact packages under `internal/`, Python scripts are lightweight utilities without extra framework assumptions.
